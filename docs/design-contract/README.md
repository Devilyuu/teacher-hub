# 设计契约 · v2.0.0

> 面向 **teaching-design-system（备课系统）** 的视觉与用语规范。
> 规格依据：`docs/superpowers/specs/2026-07-29-phase-2-3-design.md` §7.7。
> 令牌值以同目录 [`tokens.css`](tokens.css) 为准；本文只讲规则和理由。

## 这份契约要解决的唯一问题

备课系统独立部署、独立数据库、独立登录，但**在用户眼里它是本平台的「备课」模块**。
点过去风格一变，就等于换了个产品。

所以契约管的是"看起来是一家"，不管代码怎么组织。两个项目各自复制
[`tokens.css`](tokens.css) 并锁定版本，**本期不增加跨项目运行时依赖**——
等两套系统稳定且组件重合度足够高，再单独评估共享 UI 包。

## 2.0.0 为什么整套换掉

1.x 是墨黑极简：暖象牙底、墨黑主色、22px 大圆角、卡片不描边、全圆胶囊、顶部导航。
2.0.0 换成**淡青画布 + 青绿主色 + 14px 圆角 + 淡描边 + 左侧竖排导航 + 彩色功能图标**。

换的理由不是"更好看"，是**使用者变了**：平台要给别的老师用，而老师判断
"这是不是个正经系统"的参照物是教务系统、学习通、政务 OA。墨黑极简在设计圈叫克制，
在这个人群里容易读成"没做完"。**别拿"哪个更好看"来回推翻它。**

备课系统跟进 2.0.0 要做的四件事，见 `tokens.css` 头部的变更记录。

## 形状

- 淡青灰画布（`--background`）+ 纯白卡片（`--card`）
- **圆角 14px**（`--radius`）。22px 配的是卡片墙，这版是密集列表和表格
- **卡片 1px 淡描边 + 极淡阴影**。画布和卡片色差变小之后，光靠阴影卡片边界会糊
- 文字按钮圆角 ≈10px（`--radius` × 0.72），**图标按钮仍是正圆**
- 页面标题无衬线粗体。展示层衬线只留给品牌字标和登录页标题
- 中间调 `--well`：画布和白卡之间的第三档，只装"虚"的东西——托盘、空状态、
  图标圆片、未选中的筛选胶囊、表头

### 深色不是把浅色反过来

三条和浅色反着来，本平台改版时三条全踩过一遍：

1. **画布中性，不跟主色走。** 浅色画布带一点青是"纸的凉意"；同样的色相放到近黑上
   就是一层泥，青绿会变墨绿
2. **`--well` 在深色下要比卡片亮，不是暗。** 浅色的 well 是凹槽，直译到深色就成了
   一个洞。深色的 `--well` 是半透明白，叠在哪儿都自然提亮
3. **边只画一层。** 卡片已有 1px border，深色阴影里别再写 `0 0 0 1px`

深色下强调色一律**降饱和到雾面**：近黑底配高饱和原色有霓虹感。

**浮层不许用 `--card`。** 下拉、对话框、灯箱铺在遮罩上，一律走不透明的 `--popover`。

## 颜色：三层，各管各的

1. **主色 `--primary`（青绿）**：导航激活、主按钮、链接、强调数字。只有这一个主色
2. **装饰色板 `--decor-*`**：功能图标的底片。**形态锁死：淡底 11~15% + 线性描边图标，
   永不实心、永不带语义文字**
3. **语义色**：本平台只给健康度用，不进契约（备课系统没有"结题要求是否齐备"这个概念）。
   但它的形态规则要知道——**实心圆点 + 文字标签 + 胶囊底**，所以备课系统
   **别做"实心圆点 + 文字"的装饰元素**，那是语义色的形状

装饰色和语义色色相必然重叠，**区分靠形态不靠色相**。

**翠绿有确定含义**（在本平台是"结题要求已齐备"）。备课系统若要表达"完成/通过"，
沿用同一含义，不要另作他用；主色是青绿不是翠绿，两者差 20 度色相，靠形态分开。

**分类标记一律无色**（级别、类型这类正交维度）。各上一个颜色的话一行里就有四种色。

## 组件

| 组件 | 规则 |
|---|---|
| **卡片** | 圆角 `--radius`，背景 `--card`，1px `--border` 描边，阴影 `--card-shadow`；可点的卡 hover 用 `--card-shadow-hover` |
| **按钮** | 文字按钮圆角 ≈10px；图标按钮正圆。主按钮 `--primary` + `--primary-foreground`；次按钮描边 + 透明底 |
| **输入框** | 描边 `--input`，聚焦环 `--ring` |
| **导航** | 桌面**左侧竖排**，展开 `--sidebar-w`（214px）/ 收起 66px，状态记住；**手机改底部导航**，只放高频的四五项，其余进顶栏菜单 |
| **二级导航** | 下划线 tab，不做胶囊——下面紧接着往往就是筛选胶囊，两排胶囊分不出哪排是换页面 |
| **表格** | 列表要密：把上下文塞进行里。**长文本列必须限宽** + 截断 + `title` 存全文。表头吸顶贴顶栏下沿 |
| **触控** | 手机上高频操作（勾选、图标按钮、主操作）点击区不小于 44px；**桌面保持紧凑**，不全面放大 |
| **空状态** | 居中图标 + 一句「还没有 X」+ 一句说明「它会从哪来」。不要只放一句"暂无数据" |
| **加载状态** | 按钮内联文案（「保存中…」），不要整页遮罩 |
| **错误状态** | 就地红字（`--destructive`），不跳转、不清空用户已填的内容 |
| **删除** | 能撤销的删除走「移入回收站 + 撤销 Toast」，不弹确认；真删除才弹确认并写清对象 |

## 用语与语气

- **界面文案全中文**，数据库字段和代码标识符全英文。
- 说人话，不说系统话：「还没填」优于「数据为空」，「保存中…」优于「处理中」。
- 报错要说**下一步做什么**：「登录已过期，请刷新页面重新登录」优于「未授权」。
- 不用感叹号，不用「请注意」「温馨提示」这类前缀。
- 破坏性动作在按钮上写清楚对象：「删除这份教案」优于「确认」。
- **文案承诺的事界面上必须能做到**。写了「进回收站」就得有回收站入口。

## 双向入口

- 本平台的教学页显示「**打开备课系统**」（已实现）；
- 备课系统显示「**返回智能中台**」——由对方仓库实现，链接指向本平台的 `/teaching`。

两个入口的文案不要改，用户是靠这两句话建立"两边是一家"的认知的。

## 版本与升级

`tokens.css` 顶部有 `contract-version`，**本文标题的版本号必须和它一致**。升级时：

1. 本平台改 `app/globals.css`；
2. 同步 `tokens.css` 并升版本号；
3. **同步本文**：形状、颜色、组件三节的规则跟着改，标题版本号跟着升；
4. 通知备课系统复制新版本。

`lib/design-contract.test.ts` 盯着两件事：`tokens.css` 与 `globals.css` 的令牌值一致、
本文标题版本号与 `tokens.css` 一致。**2.0.0 上线时第 3 步漏了**——令牌升了、
本文还写着 22px 墨黑顶部导航，后来的人面对两份互相矛盾的"权威规范"，
所以补上了第二道门禁。

**不要反向操作**：备课系统单独改令牌值，就是两套系统悄悄分叉的开始。
